# Design System - Grafito claro y oscuro / Azul de marca

This visual system applies to product interfaces throughout the repository.

## Overview

The light theme uses the existing light graphite canvas and layered neutral surfaces. Primary fills are #12469C in both themes, with light labels and dedicated accessible foreground and border tokens. Structure comes from whitespace, surface changes and thin borders.

Typography does the heavy lifting. **Plus Jakarta Sans** is the interface family for headings, body, controls and labels in both themes; code retains the existing monospace stack. Existing type sizes, weights, line heights and tracking remain unchanged. App buttons, tabs, inputs and navigation controls use 10px corners; cards use 16px; menus and popovers use 12px; modals and floating panels use 20px. Status badges remain pills; avatars and icon-only buttons remain circular. Application brand marks use a fixed 12px radius.

Both themes use canvas as the base page surface, canvas-soft for quiet grouping, surface-card for content, and canvas-elevated for fields and overlays. On desktop, the app shell uses canvas-soft for the exterior floor and sidebar; the workspace panel uses the near-white elevated surface in light mode and retains canvas in dark mode. The graphite surfaces, text roles and independent document/export palette are preserved.

**Key Characteristics:**
- Graphite surfaces with a shared #12469C primary, accessible blue text variants and an opaque neutral focus ring.
- Neutral grouping regions and layered cards; controls and overlays retain their existing surfaces.
- Plus Jakarta Sans unifies display headings, UI and body in both themes.
- Compact 10px controls, 16px cards, 12px menus and 20px dialogs. Pills are reserved for status badges; avatars and icon-only buttons remain circular.
- Default depth is flat or a 1px hairline. Floating menus and dialogs use only a subtle shadow.
- Controls keep the application's 44px minimum touch target.

## Colors - Graphite and Blue

- Primary fill: `--color-primary` = #12469C in light and dark; channels = 18 70 156.

- Focus: opaque neutral ink, 2px, zero offset; inverted surfaces and forced-colors retain their dedicated focus treatment. Translucent decorative rings do not replace this outline.

## Dark Theme - Graphite

The optional dark theme extends the same semantic tokens using the existing graphite surface hierarchy. It shares the exact #12469C primary fill and light on-primary label with light mode, while its standalone blue text uses the brighter accessible variant. Theme selection does not change layout, radii, data or permissions.

### Appearance Preference

- The appearance control lives in /account. It uses the shared CustomSelect to choose Sistema, Claro or Oscuro (System, Light or Dark in English). The row displays the saved preference, including Sistema even while its resolved colors are light or dark. Login shows no theme or language controls and continues to use the existing preference. The selector keeps the shared touch target, keyboard navigation and visible focus. Sistema remains the initial preference when no valid stored choice exists.

### Principles
- Shared application primitives use complete Plus Jakarta Sans token roles: body-md for pagination, dropdown items, popover descriptions, confirmation descriptions and form messages; body-strong for popover, sheet and modal titles; caption-up for form labels, dropdown labels and candidate status badges. Wizard step labels and titles use caption-up and body-strong. Editable controls retain their documented iOS minimum text-size safeguard; exported documents retain their independent typography.
- Display type is defined by tight negative tracking. Body type sits at neutral spacing.
- Headings and buttons use weight 600; navigation labels may use 500; body remains 400.
- Technical labels use Plus Jakarta Sans; code uses the existing monospace stack. Role names retain compatibility with existing consumers.

### Font Loading
Plus Jakarta Sans is self-hosted as variable WOFF2 files for normal and italic Latin and Latin Extended text. The Latin normal file is preloaded; all four files are precached by the existing PWA configuration for offline use. The files and their SIL Open Font License are in `public/fonts`. There is no external font request. System sans-serif fallbacks apply if the local font cannot load. Display sizes remain unchanged.

## Layout

### Spacing System
- **Base unit**: 4px. The scale steps 4 → 8 → 12 → 16 → 24 → 32 → 40 → 64 → 96 → 128px.
- **Tokens**: `{spacing.xxs}` 4px · `{spacing.xs}` 8px · `{spacing.sm}` 12px · `{spacing.md}` 16px · `{spacing.lg}` 24px · `{spacing.xl}` 32px · `{spacing.2xl}` 40px · `{spacing.3xl}` 64px · `{spacing.4xl}` 96px · `{spacing.section}` 128px.
- **Card interiors** sit at `{spacing.lg}`–`{spacing.xl}` (24–32px); **section bands** run `{spacing.4xl}`–`{spacing.section}` (96–128px) of vertical rhythm.
- **Button sizing**: every interactive control has `min-height: 44px`. In-app controls use the shared horizontal-padding token. Height is never inferred from line-height alone.

### Grid & Container
- Pages use the shared max-width container and responsive gutters.
- Authenticated workspace content starts one shared spacing step below the header: `{spacing.md}` on mobile and `{spacing.lg}` from tablet upward. The shell owns this gap; pages keep only their internal spacing.
- The workspace header title uses Plus Jakarta Sans at the existing 20px/700 through the heading-md size and font-bold weight tokens, retaining the body-md line height and tracking and the mute color on the canvas, including linked and dynamic page titles.
- Feature grids start at one column and add columns only at documented breakpoints.
- Dense data regions must adapt without making horizontal scrolling the primary page interaction.

### Whitespace Philosophy
Whitespace is structural. White space, restrained gray grouping, and thin hairlines separate content without heavy panels. Major sections breathe while controls keep a compact internal rhythm.

### Responsive Strategy

#### Breakpoints
| Name | Width | Key Changes |
|---|---|---|
| Mobile | < 768px | Single-column stacks; navigation becomes an overlay; primary actions remain reachable |
| Tablet | 768px | 2-up card grids; condensed nav |
| Desktop | 1080px | Authenticated sidebar and full app workspace |
| Wide | 1440px+ | Wider gutters and full multi-column grids |

#### Touch Targets
Buttons, inputs, checkboxes, and circular icon controls use an explicit 44px minimum target. Text zoom may increase height; controls must not clip.

#### Collapsing Strategy
The navigation collapses behind its existing menu trigger; multi-column card grids reflow to one column; long text wraps intentionally; essential actions remain available at every width.

#### Image Behavior
Images and illustrations scale within their containers and preserve intrinsic proportions. Decorative media must not create overflow or carry essential meaning without an accessible alternative.

## Elevation & Depth

| Level | Treatment | Use |
|---|---|---|
| 0 — Flat | 1px hairline (`{colors.hairline}`), no shadow | Default feature cards, inputs, dividers, the canvas |
| 1 — Whisper | `{shadows.xs}` | Lightly raised cards |
| 2 — Floating | `{shadows.sm}` | Menus, modals, popovers and the desktop workspace |

Depth is deliberately minimal. The system prefers a crisp 1px hairline and small changes between neutral surfaces; floating surfaces use a low-alpha shadow rather than a heavy drop.

### Data tables

Product data tables use the shared `data-table` primitive: `{colors.surface-card}` for the body, `{colors.canvas-soft}` for the column header and total row, `{colors.hairline-strong}` for row separators, `caption-up` for column labels, and `body-md` for cells. The surrounding panel uses `{colors.hairline}` and `{rounded.lg}` when a frame is needed. The same tokenized cell spacing applies across desktop tables; numeric alignment and emphasis follow the meaning of each column. Tables that become stacked cards on narrow screens keep their existing mobile layout through `data-table--cards`. Printable and exported documents retain their separate `document-*` palette and layout.

### Decorative Depth
Decorative color is optional and localized. Product UI, data, and semantic states must remain understandable without gradients or color-only signals. No glows or heavy gradients.

## Shapes

### Border Radius Scale

| Token | Value | Use |
|---|---|---|
| `{rounded.none}` | 0px | Full-bleed regions and continuous calendar bands |
| `{rounded.xs}` | 4px | Checkbox indicators |
| `{rounded.sm}` | 10px | Buttons, tabs, navigation, inputs, selects and search fields |
| `{rounded.md}` | 12px | Menus, popovers and application brand marks |
| `{rounded.lg}` | 16px | Content cards and media |
| `{rounded.xl}` | 20px | Modals and floating detail panels |
| `{rounded.full}` | 9999px | Status badges, avatars and icon-only buttons |

Both themes use the same compact geometry. Semantic roles: `--radius-control` and `--radius-field` = 10px; `--radius-card` and `--radius-media` = 16px; `--radius-menu` and `--radius-brand` = 12px; `--radius-dialog` = 20px. Legacy pill-control aliases now resolve to the control radius. The legacy squircle alias resolves to the fixed brand radius, never a percentage. A select trigger remains a field even when implemented as a button.

### Geometry
Ordinary buttons are rectangles with soft 10px corners. Content cards use 16px, menus 12px and dialogs/floating panels 20px. Only status badges use pills. Avatars and icon-only buttons remain circular. Preserve continuous calendar-range bands, edge-attached sheets and document/export geometry. The approved blue palette and contrast, typography, spacing, touch targets, motion, data and permissions remain unchanged.

## Do's and Don'ts

### Do
- Keep one continuous canvas across pages; separate card and elevated surfaces with semantic tokens and hairlines.
- Reserve `{colors.link}` for links and use `{colors.focus}` for visible focus; decorative accents must stay local and optional.
- Use 8px app controls, 12px cards, and full circles only for avatars or icon-only buttons.
- Define cards and inputs with a 1px hairline (`{colors.hairline}`) before any shadow — flat is the default.
- Set display headings in Plus Jakarta Sans with the existing weight and tight negative tracking; label technical sections with the technical eyebrow token.
- Step the grey text ladder deliberately: `{colors.ink}` → `{colors.body}` → `{colors.mute}` → `{colors.faint}`.

### Don't
- Don't fill large surfaces with accent colors; decorative tokens must not become application chrome.
- Don't use pills for ordinary app buttons or inputs.
- Don't pile on shadows — depth is a 1px hairline plus, at most, a finely-layered low-alpha shadow stack.
- Don't set body copy in pure black (`#000000`) — headings use `{colors.ink}` and body steps to `{colors.body}`.
- Don't add decorative systems to application chrome; product surfaces follow the theme's neutral and semantic tokens.
- Don't loosen the display tracking — large headings retain their tight negative letter-spacing.
