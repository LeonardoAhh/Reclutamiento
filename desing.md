# Design System - Neutros claros y oscuros / Azul de marca

This visual system applies to product interfaces throughout the repository.

## Overview

The light theme uses a white canvas and soft neutral regions; the dark theme uses a near-black canvas and charcoal surfaces. Primary action fills use #2563EB from the supplied blue scale in both themes, with white labels and dedicated accessible foreground and border tokens. The supplied #3B82F6 remains a reference accent: white text on that blue reaches only 3.68:1.

Typography does the heavy lifting. **Mona Sans** is the interface family for headings, body, controls and labels in both themes; code retains the existing monospace stack. Existing type sizes, weights, line heights and tracking remain unchanged. App buttons, tabs, inputs and navigation controls, including icon-only buttons, use 10px corners; cards use 16px; menus and popovers use 12px; modals and floating panels use 20px. Badge and chip surfaces use compact 4px corners and never pills; only avatars and status dots remain circular. Application brand marks use a fixed 12px radius.

Both themes use canvas as the base page surface, canvas-soft for quiet grouping, surface-card for content, and canvas-elevated for fields and overlays. The authenticated workspace uses the canvas as a continuous page surface, without an outer frame or inset; its low-contrast square grid remains visible and fades toward the edges. The sidebar retains its palette surface. A low-contrast square grid also fades toward the edges of login and within maintenance's visual region, in both themes. Its color and spacing derive from shared tokens. Text roles and the independent document/export palette are preserved.

**Key Characteristics:**
- White and charcoal surfaces with a shared #2563EB primary, accessible blue text variants and an opaque neutral focus ring.
- Neutral grouping regions and layered cards; controls and overlays retain their existing surfaces.
- Mona Sans unifies display headings, UI and body in both themes.
- Compact 10px controls, including icon-only buttons, 16px cards, 12px menus and 20px dialogs. Badges and chips use compact 4px corners, never pills; only avatars and status dots remain circular.
- Default depth is flat or a 1px hairline. Floating menus and dialogs use only a subtle shadow.
- Controls keep the application's 44px minimum touch target.

## Colors - Neutral and Blue

### Brand & Accent
- Primary fill: `--color-primary` = #1E40AF in light and dark. It is the deepest blue of the supplied scale and the one that keeps a normal-size white label above 8.1:1.
- Hover fill: `--color-primary-active` = #1E3A8A. Pressed fill: `--color-primary-pressed` = #172554. Both deepen the fill in either theme, because lightening it would eat the label's contrast.
- Text on solid primary: `--color-on-primary` = #FFFFFF in both themes. Its contrast is 8.72:1 at rest, 10.37:1 on hover and 14.72:1 when pressed.
- Standalone primary text and functional links: `--color-primary-text` / `--color-link` = #1E40AF in light and #BFDBFE in dark. Do not use the fill token as normal-size text on neutral surfaces.
- Primary boundaries: `--color-primary-border` follows the accessible text variant. This keeps thin outlines distinguishable on stronger dark surfaces where the fill alone can fall below 3:1.
- Link hover: #1E3A8A in light and the light foreground in dark. Keep the existing underline/interaction treatment.
- Focus: opaque neutral ink, 2px, zero offset; inverted surfaces and forced-colors retain their dedicated focus treatment. Translucent decorative rings do not replace this outline.
- Semantic status fills/labels and document/export tokens remain independent from the primary foreground.

## Dark Theme - Charcoal

The optional dark theme extends the same semantic tokens using the supplied charcoal surface hierarchy. It shares the #2563EB primary fill and white on-primary label with light mode, while standalone blue text uses the brighter accessible variant. Theme selection does not change layout, radii, data or permissions.

### Appearance Preference

- The appearance control lives in /account and in the sidebar account-menu footer from tablet upward. /account uses the shared CustomSelect to choose Sistema, Claro or Oscuro (System, Light or Dark in English); the sidebar footer combines the same three icon choices and direct sign-out in one unlabeled row, with no divider between them. On mobile, sign-out remains available while theme choices are omitted. The row displays the saved preference, including Sistema even while its resolved colors are light or dark. Login shows no theme or language controls and continues to use the existing preference. Both controls keep the shared touch target, keyboard navigation and visible focus. Sistema remains the initial preference when no valid stored choice exists.
- The sidebar appearance footer uses `--icon-size-xs` (12px) for its three secondary icons and `--color-control-border` to mark the selected choice. Each icon-only option retains a 44px target and an accessible name.
- The browser preference is stored under `reclutamiento_color_scheme`; it is independent of account data and authentication. Sistema follows operating-system changes; other selections override them. Changes synchronize across tabs.
- `public/theme.js` restores the preference on `html[data-color-scheme]` before the global stylesheet loads. `useTheme` subscribes to this single controller; portals inherit the same tokens.
- If storage is unavailable, the selected theme still applies for the current visit and the selector explains that it cannot be saved.
- The browser theme-color follows the computed canvas background and is serialized to RGB for mobile browser chrome. The iOS standalone status-bar style follows the resolved light or dark mode for icon contrast. The existing PWA manifest remains a static fallback.

### Paletas seleccionables

- La paleta `Original` conserva los colores actuales. `Ocean Saas`, `Gold Void`, `Sea Glass`, `Claude Amber` y `Supabase` son opciones adicionales con variantes clara y oscura; el modo `Sistema` sigue el ajuste del dispositivo. La selección de paleta es independiente del modo y se guarda en `reclutamiento_color_palette` como `original`, `ocean-saas`, `darkmatter-remix`, `sea-glass`, `claude-amber` o `supabase`. El identificador guardado `darkmatter-remix` se conserva para mantener las preferencias existentes; `chemp` se normaliza a `sea-glass`.
- `/account` muestra los selectores de modo y paleta apilados en móvil y en una fila de dos columnas desde tablet. El menú de cuenta de la sidebar solo ofrece los tres modos de apariencia. `public/theme.js` restaura `html[data-color-palette]` antes de cargar CSS y sincroniza los cambios entre pestañas.
- En `/account`, Paleta abre una vista de detalle dentro de Ajustes, como Contraseña, y oculta las demás opciones mientras está abierta. La cabecera nombra la vista activa (`Ajustes`, `Contraseña` o `Paleta`) sin repetir ese título dentro del contenido. Las paletas se ordenan por nombre en el idioma activo. La vista usa una columna en móvil y dos desde tablet; cada opción muestra el nombre arriba, los colores de canvas, primario y tinta debajo y el indicador de selección a la derecha. La selección se aplica inmediatamente mediante controles de radio nativos, con foco visible y retorno al disparador al volver.
- Los colores se definen solo en `src/styles/global.css`, en los bloques `data-color-palette` de cada paleta para claro y oscuro. Adaptan acción primaria, superficies, texto y bordes a las referencias proporcionadas. La sidebar conserva su diseño y utiliza `--color-sidebar-surface` y `--shell-floor` de la paleta y el modo activos; no conserva una superficie clara al cambiar a oscuro. `Gold Void` aplica la paleta oro y pergamino, con tipografía y geometría globales sin cambios; los textos principales y secundarios superan 8.1:1 sobre las superficies de la paleta, los bordes de control superan 3:1 y el foco conserva el token neutral global. `Sea Glass` aplica la propuesta de contraste corregida: textos principales y secundarios conservan al menos 8.1:1 en las superficies de cada modo, y bordes de controles superan 3:1 incluso sobre superficies elevadas; el foco visible conserva el token neutral global. En oscuro usa cian y superficies azul verdosas. `Claude Amber` utiliza superficies crema y ámbar, con texto oscuro sobre su primario claro y texto ámbar más claro en oscuro para mantener AA. `Supabase` usa verde claro con texto oscuro en claro y verde profundo con texto claro en oscuro; los enlaces y el foco usan verdes con contraste suficiente. `Ocean Saas` profundiza su azul y su texto secundario hasta superar 8.1:1 en ambos modos, al nivel del resto de paletas. Los colores de error permanecen semánticos. Conservan Mona Sans, escala tipográfica, espaciado, radios, sombras y tokens de documentos/exportación. Los colores de gráficas no se agregan hasta tener consumidores reales.
- Estados por paleta: el hover neutro se deriva una sola vez en la base, `--color-surface-hover: color-mix(in srgb, var(--color-surface-strong) 97%, var(--color-ink))`, de modo que se distingue de canvas, canvas-soft, surface-card, canvas-elevated y también de surface-strong en ambos modos; ninguna paleta lo redefine. El hover y pressed del primario se alejan siempre de su etiqueta: con etiqueta clara el relleno oscurece y con etiqueta oscura aclara, y `--color-on-primary` conserva al menos 8.1:1 en los tres estados. En oscuro el enlace en hover (`--color-link-deep`) usa el texto principal, nunca el relleno primario. El texto de error supera 8.1:1 sobre todas las superficies y sobre su tinte. El hairline decorativo nunca coincide con `--color-surface-strong`: en `Sea Glass` claro el divisor es `#D6DDD8` y el verde `#64766A` queda reservado a `--color-hairline-strong`.
- Un token de color existe una sola vez por significado: no hay alias con el mismo valor y la misma función. `--color-ink` cubre títulos y cuerpo, `--color-mute` el texto secundario, `--color-surface-card` las tarjetas y `--color-canvas-elevated` campos y superficies flotantes.
- Las etiquetas blancas sobre el primario, el texto principal y el texto secundario sobre las superficies principales, así como el texto azul independiente, usan pares con contraste AA. La comprobación visual y con tecnología asistiva sigue siendo necesaria antes de certificar toda la interfaz.

Primary contrast pairs are verified above. Use dedicated foregrounds for neutral backgrounds and on-primary for filled controls; these values do not replace rendered-state verification.

- `--color-on-neutral`, `--color-on-error`, `--color-on-success` and `--color-on-warning` describe text on solid status fills; `--color-on-dark` remains text on a dark surface.

### Principles
- Shared application primitives use complete Mona Sans token roles: body-md for pagination, dropdown items, popover descriptions, confirmation descriptions and form messages; heading-sm for Modal, Sheet and FormSheet titles; body-strong for popover titles; caption-up for form labels, dropdown labels and candidate status badges. Wizard step labels and titles use caption-up and body-strong. Editable controls retain their documented iOS minimum text-size safeguard; exported documents retain their independent typography.
- Pagination uses one compact shared control: previous and next icon actions surround an editable page number and a visible localized total. The page input has only a bottom border, emphasized with the focus token while editing, plus its accessible label, numeric editing and 44px target; navigation actions keep 44px targets, tokenized focus and palette colors. Forced-colors mode retains the system focus outline. The optional sticky footer uses a hairline and the current theme surface, with safe-area spacing. Page-specific layout may position the footer but does not restyle its controls.
- Display type is defined by tight negative tracking. Body type sits at neutral spacing.
- Headings and buttons use weight 600; navigation labels may use 500; body remains 400.
- Technical labels use Mona Sans; code uses the existing monospace stack. Role names retain compatibility with existing consumers.

### Font Loading
Mona Sans is self-hosted as variable WOFF2 files for normal and italic text. The normal file is preloaded; both files are precached by the existing PWA configuration for offline use. The files and their SIL Open Font License are in `public/fonts`. There is no external font request. System sans-serif fallbacks apply if the local font cannot load. Type sizes, weights, line heights and tracking remain unchanged.

## Layout

### Spacing System
- **Base unit**: 4px. The scale steps 4 → 8 → 12 → 16 → 24 → 32 → 40 → 64 → 96 → 128px.
- **Tokens**: `{spacing.xxs}` 4px · `{spacing.xs}` 8px · `{spacing.sm}` 12px · `{spacing.md}` 16px · `{spacing.lg}` 24px · `{spacing.xl}` 32px · `{spacing.2xl}` 40px · `{spacing.3xl}` 64px · `{spacing.4xl}` 96px · `{spacing.section}` 128px.
- **Card interiors** sit at `{spacing.lg}`–`{spacing.xl}` (24–32px); **section bands** run `{spacing.4xl}`–`{spacing.section}` (96–128px) of vertical rhythm.
- **Button sizing**: every interactive control has `min-height: 44px`. In-app controls use the shared horizontal-padding token. Height is never inferred from line-height alone.

### Grid & Container
- Pages use the shared `.container` with a 90rem maximum width and responsive gutters. This is the only global page-container width; narrower or wider limits belong to specific content regions and must use their existing semantic tokens.
- Long-form text and focused content regions may use the shared 65ch reading-width token without changing the page container.
- Authenticated workspace content starts one shared spacing step below the header: `{spacing.md}` on mobile and `{spacing.lg}` from tablet upward. The shell owns this gap; pages keep only their internal spacing.
- The workspace header title uses Mona Sans at the existing 20px/700 through the heading-md size and font-bold weight tokens, retaining the body-md line height and tracking and the mute color on the canvas, including linked and dynamic page titles.
- Feature grids start at one column and add columns only at documented breakpoints.
- Dense data regions must adapt without making horizontal scrolling the primary page interaction.

### Whitespace Philosophy
Whitespace is structural. White space, restrained gray grouping, and thin hairlines separate content without heavy panels. Major sections breathe while controls keep a compact internal rhythm.

### Responsive Strategy

#### Breakpoints
| Name | Width | Key Changes |
|---|---|---|
| Mobile | < 768px | Single-column stacks; navigation becomes an overlay; primary actions remain reachable |
| Tablet | 768px | 2-up card grids; condensed nav |
| Desktop | 1080px | Authenticated sidebar and full app workspace |
| Wide | 1440px+ | Wider gutters and full multi-column grids |

#### Touch Targets
Buttons, inputs, checkboxes, and icon controls use an explicit 44px minimum target. Text zoom may increase height; controls must not clip.

#### Collapsing Strategy
The navigation collapses behind its existing menu trigger; multi-column card grids reflow to one column; long text wraps intentionally; essential actions remain available at every width.

#### Image Behavior
Images and illustrations scale within their containers and preserve intrinsic proportions. Decorative media must not create overflow or carry essential meaning without an accessible alternative.

## Elevation & Depth

| Level | Treatment | Use |
|---|---|---|
| 0 — Flat | 1px hairline (`{colors.hairline}`), no shadow | Default feature cards, inputs, dividers, the canvas |
| 1 — Whisper | `{shadows.xs}` | Lightly raised cards |
| 2 — Floating | `{shadows.sm}` | Menus, modals, popovers and the workspace |

Depth is deliberately minimal. The system prefers a crisp 1px hairline and small changes between neutral surfaces; floating surfaces use a low-alpha shadow rather than a heavy drop.

### Data tables

Product data tables use the shared `data-table` primitive: `{colors.surface-card}` for the body, `{colors.canvas-soft}` for the column header and total row, `{colors.hairline}` for quiet row separators, `caption-up` for column labels, and `body-md` for cells. Row headers use `body-strong` without uppercase styling. The surrounding panel uses `{colors.hairline}` and `{rounded.lg}` when a frame is needed. Paginated tables frame the table wrapper only; the shared `Pagination` follows outside that frame with tokenized spacing. The same relationship applies when a table becomes a stacked card list on narrow screens. The same tokenized cell spacing applies across desktop tables; numeric alignment and emphasis follow the meaning of each column. Tables that become stacked cards on narrow screens keep their existing mobile layout through `data-table--cards`. Printable and exported documents retain their separate `document-*` palette and layout.

### Decorative Depth
Decorative color is optional and localized. Product UI, data, and semantic states must remain understandable without gradients or color-only signals. No glows or heavy gradients.

## Do's and Don'ts

### Do
- Keep one continuous canvas across pages; separate card and elevated surfaces with semantic tokens and hairlines.
- Reserve `{colors.link}` for links and use `{colors.focus}` for visible focus; decorative accents must stay local and optional.
- Use 8px app controls, 12px cards, and full circles only for avatars or status dots; icon-only buttons use the control radius.
- Define cards and inputs with a 1px hairline (`{colors.hairline}`) before any shadow — flat is the default.
- Set display headings in Mona Sans with the existing weight and tight negative tracking; label technical sections with the technical eyebrow token.
- Step the grey text ladder deliberately: `{colors.ink}` for headings and body, `{colors.mute}` for secondary text. There is no third step; adding one means adding a token with its own verified contrast, not an alias of an existing value.

### Don't
- Don't fill large surfaces with accent colors; decorative tokens must not become application chrome.
- Don't use pills for ordinary app buttons or inputs.
- Don't pile on shadows — depth is a 1px hairline plus, at most, a finely-layered low-alpha shadow stack.
- Don't set body copy in pure black (`#000000`) — headings and body use `{colors.ink}`.
- Don't add decorative systems to application chrome; product surfaces follow the theme's neutral and semantic tokens.
- Don't loosen the display tracking — large headings retain their tight negative letter-spacing.
